Architectural & Design Justifications

1. Asynchronous Decoupled Bulk Processing

When processing hundreds or thousands of recipients, synchronous processing would cause client HTTP connection timeouts. We utilize FastAPI's BackgroundTasks worker pattern: the API validates the initial envelope, saves the job with status PENDING, immediately returns 202 Accepted with a tracking job_id, and performs generation asynchronously.

2. Fault Isolation (Failure Handling)

A corrupted name, invalid email, or transient file I/O error on recipient #15 must never abort the remaining 999 recipients. The worker encapsulates generation in per-recipient try...except boundaries. Erroneous records are flagged as FAILED with precise error causes, while successful ones receive SUCCESS status, resulting in a clean PARTIALLY_COMPLETED or COMPLETED aggregate job status.

3. Dual-Format Generation & Dynamic QR Verification

Using Pillow at 300 DPI, we generate high-resolution print-ready PDFs and web-crisp PNGs simultaneously. Every certificate embeds a dynamic QR code pointing to the live /api/v1/certificates/verify/{code} endpoint for instant tamper-proof validation.

4. Relational Data Model (SQLAlchemy)

Normalized schema separating CertificateJob (batch envelope and aggregate counters) from CertificateRecord (per-recipient status, file paths, and individual error reasons) with foreign key cascading and indexed certificate codes.
